## Urteil

**Bestanden** auf main `f1bf42bb`: 2.880 von 2.880 Zellen, gleicher Hash in zwei Läufen und über zwei frisch geladene
Datenbanken, Exit 0 ohne einen einzigen Netzversuch. Der Providerwechsel ändert keine Zahl (gemessen am Kopf von !13,
der Lauf-Code ist auf main unverändert).

**Blocker außerhalb des Kriteriums (66-6):** Der README-Weg `uv run uc3 lauf --alle` hängt auf einer frisch geladenen
Datenbank im dritten Monat (siehe unten). EA-4 prüft nur 2024-08 und bleibt bestanden; die Jury, die dem README folgt,
bleibt aber stehen.

Einschränkung: Der wörtliche Befehl aus dem Kriterium bricht an `regeln laden` ab (66-1). Die Jury braucht den Weg aus
`uc3/README.md`, nicht den aus dem Issue. Der Port 5433 war auf dem Prüfrechner belegt; geprüft wurde mit 5444.

## `lauf --alle` auf frischer Datenbank (66-6)

Gemessen 16:01 bis 16:12 auf DB B nach `down -v` (main `f1bf42bb`), Befehl wie im README:
`uv run uc3 lauf --alle`.

| Monat | Dauer | Ergebnis |
|---|---|---|
| 2024-08 | wenige Sekunden | `unveraendert` (schon gerechnet) |
| 2024-09 | 13 s | `fertig`, gezählt 393.454 |
| 2024-10 | über 9 min, 100 % CPU, von mir abgebrochen | `abgebrochen` |

Der hängende Query steht in `uc3/statagent/bereinigung.py:131-157` (Regel E07 Fortschreibung: Vormonat `vm` gegen die
neue Lieferung mit `NOT EXISTS` auf `bereinigt.abschnitt`). Die Lauf-Transaktion begann 16:02:05; die letzte
automatische Statistik der Tabelle stammt von 16:02:56 und kannte beim Planen weder 2024-09 noch 2024-10. Bei geschätzt
je einer Zeile wählt Postgres eine verschachtelte Schleife über rund 300.000 mal 400.000 Zeilen.

Gegenprobe: Nach der automatischen Statistik läuft `uv run uc3 lauf --lieferung 2024-10` allein in **19 s**
(gezählt 391.033). `tests/abnahme/66_monate_mit_analyze.sh` rechnet die übrigen Monate mit `ANALYZE bereinigt.abschnitt`
vor jedem Lauf.

Vorschlag an UC3: nach dem Einfügen der Lieferung in `bereinigt.abschnitt` im Lauf selbst `ANALYZE bereinigt.abschnitt`
ausführen, so wie `uc3/statagent/zaehlung.py:182-185` es für die Temp-Tabellen macht. In der eigenen Transaktion sieht
ANALYZE die gerade eingefügten Zeilen.
